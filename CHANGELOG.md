# Changelog

The running version shows at the top of the probe window, at the end of the on-screen readout's first line,
in `ReShade.log` (`HUD-less probe 1.0.0 ... loaded`, plus `updated from version ...` when it changed),
in ReShade's add-on list and in the file's Properties > Details.

| Version | Step | Changes |
|---|---|---|
| 1.0.0 | release | First public release. MIT licence, third-party notices, GitHub Actions build (both variants on every push, a release with the zip on a version tag). Package zip also holds the licences. README: download from Releases; module icon softness noted as Factorio's own. |
| 0.16.0 | release candidate | Factorio updates: the world layer snapshot points are also read off the frame's structure (world target = the full-size target with most draws; tiles = its most used sprite shader, first draw; floor / cloud passes = full-screen triangles on it, early / late; composite = the first full-screen triangle elsewhere afterwards). Checked against the Nauvis trace: the same points as built in. If the built-in shaders are not drawn for 5 s and the structure gives the same answer for about a second, those points are used (logged, shown in the Motion vectors tab with a structure check). No world layers in space (platform starfield). Factorio update notice removed. README: step-by-step install, update and removal. |
| 0.15.0 | release candidate | README rewritten as a user guide (requirements, install, first start, settings, how it works, surfaces, troubleshooting, known limits); the step-by-step notes moved to DEVLOG.md. `package_release.bat` builds the release add-on and zips it with README and changelog into `dist\`. Release build defaults: multiplier Auto, readout off (Ctrl+F11). |
| 0.14.1 | 9 | Surfaces without a cloud pass (Vulcanus): the object, after-cloud, air-split and world snapshots are all taken right before the composite pass instead (no separate air layer there; flying robots count as objects). Without a floor pass the floor snapshot is the ground one. The Motion vectors tab lists which snapshots are missing when they are incomplete. |
| 0.14.0 | 9 | World layer snapshots are copied straight into the bridge's shared textures (two sets, alternating per frame) instead of into the add-on's own textures and then again at present: six full-screen copies per frame less on Factorio's GPU work (about 170 MB of copy traffic per frame at 1440p). The preview (developer tools) still uses the old path. Motion vectors tab: fine-tuning sliders and debug views in collapsed sections, debug view choices on two rows. |
| 0.13.2 | 9 | Shader compile notice top left (also with the readout off, also without frame generation) until the motion shaders are ready, with progress; stays if they failed. Settings: hints wrap at the window edge, sliders leave room for their labels, the air split is a collapsed section with the shader choice in a drop-down (the changing list of air stage shaders no longer moves the settings below). Readout no longer repeats the camera line as an orange status. |
| 0.13.1 | 9 | Fix: 0.13.0's shaders did not compile in the game (a variable named `pass`, reserved by d3dcompiler_47) - no motion vectors, layers or debug view. The readout now says so in orange when motion is not running (compiling, or failed). |
| 0.13.0 | 9 | Performance: the block search split into three passes. cs_block_pre settles most blocks (bare ground, edges, alt-mode icons) and marks the ones that need a mover search; cs_mover runs those searches with 64 threads per block instead of one (a single searching block used to hold up 31 others in its warp, and each search kept a 169-entry array per thread); cs_block finishes the rest. Same decisions as before. Shader compile starts at add-on load. Readout: searched / wide-searched blocks and movers found per frame. |
| 0.12.3 | 8c | GPU motion back down: the hot block-matching loops unrolled again (the row loops of 0.12.2 compiled fast but ran slower, 5.4 ms); fewer inlined copies instead, so the one-time background compile stays shorter than 0.12.1's. Scene-cut check waits only for the first part of the motion passes (up to the camera's coarse search), the rest runs while the CPU waits: less latency. Readout: GPU motion per stage (camera / blocks / rest). |
| 0.12.2 | 8c | Start-up fix: the motion shaders compiled on the render thread (black screen ~2 min at start with 0.12.1). Now compiled on a worker thread - the game starts normally, motion vectors switch on when done (zero until then) - and cached in `factorio_fg_shaders.cache` next to the add-on, so later starts load them at once. Shader loops over rows instead of fully unrolled (much less for the compiler; same results). Compile times in ReShade.log. |
| 0.12.1 | 8c | Air stage split (snapshot before the first draw of D82AC825, selectable): alt-mode icons (cyan) get the camera motion where it genuinely matches - no search, no shifted copies on rows of identical icons; flying robots (yellow) keep the search. Wide mover search for fast trains (up to +-192 px per frame instead of +-48, only where the normal search finds nothing; toggle). Found movers refined at half res (were up to 2 px off). Per-pixel repeating-pattern cost capped so fast movers keep their edges. |
| 0.12.0 | 8c | Fourth world layer, air: snapshots right after the cloud pass (703619E0) and of the finished world right before the composite (575CE4FC); what differs was drawn in the air stage - flying robots, alt-mode icons - and gets the nearest depth (was missing: bots only showed by their shadows on the floor layer). Debug view yellow = air, *World (with air)* snapshot view and preview. |

| 0.11.0 | 8b | Three world layers: ground (after 7C158CCA #2, tiles + grass; always camera, far), floor (after BCD79626: belts, pipes, inserters, shadows; middle), objects (before 703619E0; near). World layers on by default. Debug and preview views for all three snapshots. |
